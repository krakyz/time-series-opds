# Прогнозирование энергопотребления и выявление аномалий

Проект посвящен анализу почасового энергопотребления, построению моделей прогноза на 24 часа вперед и выявлению аномалий во временном ряду. В работе используются исторические значения потребления, календарные признаки, лаги, скользящие статистики и погодные/энергетические внешние признаки.

Основной файл сдачи: `notebooks/05_final_report.ipynb`. В нем собраны этапы EDA, статистического моделирования, ML/DL-моделей, поиска аномалий и финального пайплайна.

## Описание временного ряда

**Источник:** [TimeSeriesCourse/OLD Versions/2026/datasets
/OPDS](https://github.com/MVRonkin/TimeSeriesCourse/tree/83a3a8586d7ae4240d10e3c671d2a13ab25276c1/OLD%20Versions/2026/datasets/OPDS).

В качестве целевой переменной используется `Consumption` - почасовое энергопотребление. После подготовки данные приводятся к формату временного ряда с колонками `ds` и `y`, где `ds` - временная метка, а `y` - целевая переменная.

| Характеристика | Значение |
|---|---|
| Частота | 1 час |
| Период наблюдений | 2015-01-01 - 2019-12-31 |
| Целевая переменная | `Consumption` |
| Формат для моделей | `unique_id`, `ds`, `y` |
| Основной горизонт прогноза | 24 часа |
| Train-период | 2015-2018 |
| Test-период | 2019 |
| Основные сезонности | Суточная, недельная |

Внешние признаки используются как дополнительное описание состояния системы и окружающей среды.

| Группа признаков | Колонки |
|---|---|
| Погодные признаки | `temperature`, `radiation_direct_horizontal`, `radiation_diffuse_horizontal` |
| Энергетические признаки | `Wind`, `Solar`, `Wind+Solar` |
| Календарные признаки | Час, день недели, месяц, выходной день |
| Лаговые признаки | Лаги целевой переменной, включая 24 и 168 часов |
| Rolling-признаки | Скользящие средние и стандартные отклонения |

## Постановка задачи

Цель работы - построить и сравнить несколько подходов к прогнозированию энергопотребления, а также собрать воспроизводимый пайплайн с детекцией аномалий.

| Элемент задачи | Решение в проекте |
|---|---|
| Тип задачи | Прогнозирование временного ряда |
| Горизонт | 24 часа вперед |
| Целевая переменная | `Consumption` / `y` |
| Метрики | MAE, RMSE, SMAPE |
| Базовая модель | `SeasonalNaive_168h` |
| Финальная модель пайплайна | `RandomForestRegressor` |
| Детекция аномалий | Z-score, Isolation Forest, LOF, One-Class SVM, голосование |
| Основной критерий сравнения | SMAPE, дополнительно MAE и RMSE |

## EDA

На этапе разведочного анализа были проверены структура данных, временной индекс, пропуски, дубликаты и сезонность. Ряд имеет выраженную суточную и недельную структуру, поэтому для прогнозирования важны лаги 24 и 168 часов.

Ключевые выводы EDA:

| Наблюдение | Вывод |
|---|---|
| Временной индекс | Данные приведены к регулярному почасовому формату. |
| Пропуски | Критичных пропусков в целевой переменной после подготовки нет. |
| Сезонность | Наиболее заметны суточные и недельные повторения. |
| Стационарность | Ряд содержит выраженную структуру и сезонность, поэтому простая стационарная модель недостаточна. |
| Признаки | Для ML-моделей нужны календарные, лаговые, rolling- и внешние признаки. |

## Статистические модели

Во втором и итоговом ноутбуках были проверены ручные и автоматические статистические модели. Для оценки использовался rolling backtesting. AutoARIMA формально относится к статистическим моделям, но в финальном прогоне она исключена из основного сравнения из-за высокой вычислительной стоимости на почасовом ряде.

| Модель | Роль в работе | Основной результат |
|---|---|---|
| `SeasonalNaive_24h` | Суточный сезонный бейзлайн | Лучшая модель на rolling backtesting: SMAPE около 4.71%. |
| `SeasonalNaive_168h` | Недельный сезонный бейзлайн | Лучшая на первых 24 часах test: SMAPE около 4.41%. |
| `HoltWinters_AAA_24h` | Экспоненциальное сглаживание | Стабильная статистическая модель, но хуже сезонных бейзлайнов. |
| `Theta_24h` / `AutoTheta_24h` | Theta-подход | Работает приемлемо, но не превосходит сезонный naive. |
| `AutoETS_24h` | Автоматический ETS | Используется для сравнения, но требует больше времени. |
| `Prophet` | Модель с трендом и сезонностями | На первых 24 часах test уступила бейзлайнам. |

Для данного ряда сильный сезонный бейзлайн уже дает конкурентное качество. Это означает, что сложные статистические модели нужно сравнивать не только между собой, но и с простыми сезонными правилами.

## ML- и DL-модели

ML-модели обучались на табличном представлении временного ряда: календарные признаки, лаги, rolling-статистики и внешние погодные/энергетические признаки. Такой подход оказался наиболее сильным в финальном сравнении.

Результаты ML-моделей на полном test-периоде:

| Модель | MAE | RMSE | SMAPE, % |
|---|---:|---:|---:|
| RandomForest | 1.431 | 2.306 | 2.612 |
| XGBoost | 1.539 | 2.438 | 2.745 |
| LightGBM | 1.542 | 2.407 | 2.750 |
| HistGradientBoosting | 1.545 | 2.397 | 2.757 |
| Ridge | 4.407 | 5.682 | 7.789 |

Результаты DL/ML-моделей на коротком горизонте сравнения:

| Модель | MAE | RMSE | SMAPE, % |
|---|---:|---:|---:|
| NBEATS | 1.669 | 2.169 | 3.518 |
| LightGBM | 1.940 | 2.736 | 3.762 |
| NHITS | 1.879 | 2.357 | 3.958 |
| HistGradientBoosting | 2.109 | 2.827 | 4.060 |
| XGBoost | 2.479 | 3.156 | 4.756 |
| RandomForest | 2.602 | 3.340 | 5.079 |
| LSTM | 5.503 | 6.071 | 10.615 |

Итоговый выбор для пайплайна - `RandomForestRegressor`. Он показал лучшее качество на полном test-периоде, быстро обучается и дает воспроизводимый результат без сложной настройки DL-инфраструктуры.

## Детекция аномалий

Для поиска аномалий использовались несколько независимых методов. Итоговая метка `is_anomaly` строится голосованием, чтобы снизить зависимость от одного алгоритма.

| Метод | Количество найденных точек |
|---|---:|
| Z-score | 56 |
| Isolation Forest | 263 |
| LOF | 263 |
| One-Class SVM | 264 |
| Голосование `is_anomaly` | 101 |

Так как в исходных данных нет ручной разметки аномалий, дополнительно был проведен синтетический benchmark: в ряд искусственно добавлялись выбросы, после чего сравнивалась способность методов находить эти точки.

| Метод | Precision | Recall | F1 |
|---|---:|---:|---:|
| LOF | 0.77 | 0.81 | 0.79 |
| Голосование `is_anomaly` | 0.82 | 0.67 | 0.74 |
| Z-score | 0.79 | 0.50 | 0.61 |
| One-Class SVM | 0.19 | 0.76 | 0.30 |
| Isolation Forest | 0.09 | 0.38 | 0.14 |

LOF лучше всего сработал на синтетическом тесте по F1, а голосование дало более строгий и интерпретируемый результат с высокой precision.

## Финальный пайплайн

Финальный пайплайн реализован в `src/pipeline.py` и может быть запущен через `main.py`. Он выполняет полный цикл обработки без ручного переноса кода из ноутбуков.

Этапы пайплайна:

1. Загрузка подготовленного временного ряда.
2. Генерация признаков для ML-модели.
3. Разделение данных на train и test без перемешивания.
4. Обучение `RandomForestRegressor`.
5. Сравнение с `SeasonalNaive_168h`.
6. Поиск аномалий несколькими методами.
7. Синтетическая проверка качества детекции аномалий.
8. Сохранение таблиц, графиков и краткого отчета.

Итоговое сравнение пайплайна:

| Модель | MAE | RMSE | SMAPE, % |
|---|---:|---:|---:|
| RandomForest | 1.431 | 2.306 | 2.612 |
| SeasonalNaive_168h | 2.559 | 4.469 | 4.682 |

`RandomForestRegressor` улучшил качество относительно недельного сезонного бейзлайна. При этом время обучения в финальном прогоне составило около 27 секунд, а время инференса - меньше 1 секунды.

## Запуск проекта

Установка основных зависимостей:

```bash
pip install -r requirements.txt
```

Если DL-модели запускаются локально на NVIDIA GPU, CUDA-версию PyTorch можно поставить отдельно:


## Валидация и ограничения

| Аспект | Как учтено |
|---|---|
| Утечка данных | Train/test деление выполняется по времени, без перемешивания. |
| Бейзлайн | Финальная модель сравнивается с недельным сезонным naive. |
| Статистические модели | Оцениваются через rolling backtesting. |
| ML-модели | Оцениваются на отложенном test-периоде 2019 года. |
| Аномалии | Проверяются несколькими методами и синтетическим benchmark. |
| Воспроизводимость | Основная логика вынесена в `src/` и запускается через `main.py`. |

Ограничения работы:

| Ограничение | Комментарий |
|---|---|
| Нет ручной разметки аномалий | Метки аномалий являются кандидатами для последующей экспертной проверки. |
| Метрики зависят от исторического test-периода | При изменении периода качество может отличаться. |
| Внешние признаки нужны заранее | Для промышленного прогноза нужно понимать, какие погодные и энергетические признаки доступны на момент прогноза. |
| AutoARIMA исключена из финального сравнения | Модель слишком дорогая по времени для полного регулярного запуска на почасовом ряде. |

## Итог

Лучший практический результат в проекте дала ML-модель `RandomForestRegressor` с SMAPE около 2.61% на полном test-периоде. Простые сезонные модели остаются сильными бейзлайнами, особенно на коротком горизонте, поэтому они использованы как обязательная точка сравнения. Для аномалий наиболее полезными оказались LOF и голосование нескольких детекторов.
